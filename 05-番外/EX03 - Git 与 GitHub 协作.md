# EX03：Git 与 GitHub 协作

> [[课程总览|返回课程总览]] · [[05-番外/EX02 - 如何合理获取原作素材|上一篇]] · [[05-番外/EX04 - 项目目录、素材管理与版本管理|下一篇]]

## 开场

展示一个有清晰提交记录和远程备份的课程项目，说明 Git 不只是发布代码，也是管理试错过程的工具。

## Git 与 GitHub 的区别

区分本地版本管理和远程代码托管，说明两者如何配合，以及各自解决什么问题。

## 版本管理的基本对象

介绍工作区、暂存区、提交和历史记录之间的关系，建立对一次变更如何被保存的直观认识。

## 创建与接收项目

说明新项目开始版本管理和接收已有项目的两种场景，让观众能够选择适合当前项目的起点。

## 编写有用的提交记录

说明如何按功能或问题组织提交，让每次记录都能表达一个清晰的变化，而不是把大量互不相关的修改混在一起。

## 忽略不应提交的内容

整理构建产物、临时文件、编辑器配置和本地环境信息等内容，避免它们污染项目历史或泄露本机信息。

## 分支与实验

介绍使用分支隔离实验性功能和高风险修改，让主线保持可运行并方便比较不同方案。

## 与 GitHub 同步

说明本地提交、远程仓库、推送和拉取之间的关系，建立个人备份和多人协作的基本流程。

## Issue 与讨论

介绍如何记录 Bug、功能想法和待办事项，让问题从聊天中的一句话变成可以追踪的工作项。

## 协作与合并

说明多人修改同一项目时如何分工、检查和合并，并概括出现冲突时需要回到内容本身解决问题。

## 发布版本与回滚

介绍如何为可分享的版本留下明确标记，以及发现问题时如何回到较早的稳定状态。

## Dog Battle 的实践流程

把 Git 工作流应用到课程项目，从创建、迭代、测试到发布建立一套可重复的记录方式。

## 结尾

总结 Git 和 GitHub 在备份、协作与回溯方面的作用，并预告下一篇：如何合理获取原作素材。
