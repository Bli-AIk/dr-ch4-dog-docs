# EX04：项目目录、素材管理与版本管理

> [[课程总览|返回课程总览]] · [[05-番外/EX03 - Git 与 GitHub 协作|上一篇]] · [[05-番外/EX05 - Kristal 的社区库都有啥|下一篇]]

## 开场

展示一个经过整理的 Kristal 项目，说明清晰的目录和资源管理会如何影响开发、协作和发布。

## 为什么要管理项目结构

说明文件随意堆放会带来的查找、引用、冲突和发布问题，建立“目录也是项目设计的一部分”的意识。

## 区分项目内容

区分脚本、素材、语言文件、配置、工具和构建产物，明确哪些内容属于源文件，哪些内容可以重新生成。

## 组织 Kristal Mod 目录

结合课程项目介绍主要目录的职责，让观众知道新功能应放在哪里，以及如何避免破坏引擎的自动发现规则。

## 管理图片、音频和字体

说明不同类型素材的存放、命名和引用方式，保持资源路径稳定并降低后续替换成本。

## 管理语言与文本资源

介绍对话、菜单文字和本地化内容的组织方式，避免把文本散落在难以维护的脚本中。

## 统一命名和路径

建立文件、目录、对象和资源的命名习惯，让项目内容容易搜索，也减少大小写和路径差异造成的问题。

## 区分开发文件与发布文件

说明对象编辑器、调试工具、临时素材和测试内容如何与最终发布版本区分开。

## 素材来源与记录

为外部素材记录来源、作者、许可证和修改情况，确保以后能够判断素材是否适合继续使用或发布。

## 版本管理的基本思路

介绍版本管理需要保存什么、忽略什么，以及如何通过小而清晰的变更记录追踪项目演变。

## 发布前的目录检查

从路径、引用、缺失素材和无关文件几个方面检查项目，形成一套每次发布都能重复执行的整理流程。

## 结尾

回顾目录、素材和版本记录之间的关系，并预告下一篇：Git 与 GitHub 协作。
