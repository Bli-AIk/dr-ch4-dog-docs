## Lua 在 Kristal 项目中的位置

Lua 是一种**解释型**语言——不用编译，游戏运行的时候直接读源码执行。你的项目里所有 `.lua` 文件，都会被 Kristal 自动加载：`scripts/` 目录下的脚本按约定位置自动发现，不需要手动注册（第 02 集看过目录结构了）。

在 Kristal 里写 Lua，大部分时候不是在"写逻辑"，而是在**描述**：这个敌人是什么（数值、行为）、这个波次怎么动（生成、移动）、这句对话说什么。代码更像是"给游戏写的剧本"，而不是"给计算机写的指令"。

## 变量与基本值

变量就是给值起个名字。Lua 里常用的基本值有四种：

```lua
local hp = 450          -- 数字
local name = "神烦狗"   -- 字符串（文字），单双引号都行
local is_spared = false -- 布尔值：true / false
local nothing = nil     -- "什么都没有"
```

注意 `local` 这个关键字——它声明"这是局部变量"。Kristal 的代码里 `local` 到处都是，是标准写法；不加 `local` 的变量是全局的，容易互相污染，新手阶段一律写 `local` 就对了。

值有四个最常见的基本类型：数字（number），字符串（string），布尔值（bool/boolean），还有*万恶的* nil（null）。

再展开说说**类型**这件事。Lua 是**动态类型**语言——变量自己没有类型，类型跟着值走（上面刚见过）。

会其他语言的读者对照一下：Lua 的变量没有类型声明，`local x = 10` 之后还可以 `x = "字符串"`——类型跟着值走，很自由，但也意味着拼错变量名时不会有人提醒你。

它简单，但有两个小坑要知道：

- **自动转换很有限**：`"10" + 5` 能得到 15（Lua 会试着把数字字符串转成数字），但 `"abc" + 5` 直接报错；而且 `"10" == 10` 是 **false**——比较时不做转换。想要显式转换，用 `tonumber("10")` 和 `tostring(10)`；
- **类型不检查的代价**：拼错变量名、传错参数类型，Lua 都不吭声，运行到那一刻才炸。所以第 01 集配的 LuaLS 补全和诊断值得一直开着——它能在写的时候提醒你。

如果你是从 C#、C++、Rust 这类**静态类型**语言过来的，看到"没有类型系统"可能会有点慌——这很正常。《实用 Common Lisp 编程》里提到，连 C++ 界的两位老资历 Robert Martin（Uncle Bob）和 Bruce Eckel 都曾是强类型的忠实信徒——Uncle Bob 自嘲自己"做了很多年的静态类型顽固分子"，Eckel 也承认自己"一度无条件信奉强类型检查"（"静态类型偏执狂"）。

但有意思的是，两人后来都转变了：一个被测试驱动开发（TDD）说服，一个被 Python 说服，最后殊途同归——**正确性靠的是"强测试"，不是"强类型"**。

btw，作者本人写 Lua 之前是 Rustacean——也曾是个静态类型偏执狂本狂——但我现在想说：动态类型真没有你想象中那么吓人。游戏脚本这种"描述性"的代码，恰恰是动态类型最舒服的场景。

## 条件与流程控制

判断用 `if`，循环用 `for` / `while`，和大多数语言一样，只是写法上有 Lua 的怪癖：**块结束要写 `end`**。

```lua
if hp > 0 then
    print("还活着")
elseif hp == 0 then
    print("正好零血")
else
    print("何意味，怎么负数了？")
end

for i = 1, 10 do      -- 从 1 到 10（**含 10**）
    print(i)
end

while hp > 0 do
    -- 一直循环，直到条件不成立
end

-- 哦天哪。大括号，你在哪里？！
```

真实场景：dog.lua 里判断"这回合是不是 GB 回合"，就是 `if self.selected_wave ~= "gb" then` 这种写法——`~=` 是"不等于"（其他语言是 `!=`，这是 Lua 的另一个怪癖）。

## 表与数据组织

Lua 里最重要、也最"不一样"的东西是**表（table）**。一句话：**表什么都能装**——它同时是"数组"和"字典"。

```lua
-- 数组：一串东西
local waves = { "bone", "gb", "car" }
print(waves[1])   -- bone（注意：Lua 的下标从 1 开始！）
print(#waves)     -- 3（# 是取长度）

-- 字典：名字对应值
local dog = { name = "神烦狗", hp = 450 }
print(dog.name)   -- 神烦狗
print(dog["hp"])  -- 450（两种写法等价）
```

会其他语言的读者：Lua 的表 ≈ 别的语言的"数组 + 对象/字典"合体。JSON 你总见过吧——Lua 的表基本就是 JSON 加上了数组下标。

真实场景：dog.lua 里 `self.waves = { "bone", "gb", "car" }` 就是一张表；你的 `mod.json` 也是"表"的另一种写法（JSON 格式，Kristal 加载后就是一张表）。

## 函数与参数

函数就是把一段行为包起来，可以传参数、可以返回值：

```lua
local function add(a, b)
    return a + b
end

print(add(2, 3))  -- 5

-- 匿名函数：不取名字，直接写
local on_click = function()
    print("被点了")
end
```

Lua 里函数是一等公民——它可以被存进变量、塞进表、当参数传。Kristal 代码里最常见的用法就是**回调**：把"要发生的事"写成匿名函数，交给框架在合适的时机调用。比如 ACT 的触发逻辑，经常就是"如果选了这个选项，就执行这个函数"。

## 文件与模块

一个 `.lua` 文件就是一个"模块"。Kristal 会按目录自动加载它们，并在加载时执行文件最外面的代码（`local X, super = Class(...)` 这行就是在"定义这个类"）。

你不需要手动 `require` 别人——Kristal 的注册表会按路径自动发现并加载所有脚本，然后按照脚本类型放进对应的"表"里（`enemies`、`waves`、`items`……）。所以记住一个原则就行：**一个脚本文件 = 一个对象/类**，文件放在哪个目录，它就属于哪一类。

## 对象式写法的阅读方式（重点）

这一节是本篇最重要的一节——Kristal 的代码几乎全是"对象式"的，而你不需要会写，**先学会读**就行。

如果你学过**面向对象**（OOP）相关的内容，这部分会很好理解。

看下面 dog.lua 的开头部分：

```lua
local Dog, super = Class(EnemyBattler)

function Dog:init()
    super.init(self)
    self:setActor("dog")
    self.max_health = 450
    self.health = 450
end
```

逐行翻译：

- `Class(EnemyBattler)`：**定义一个新类，继承自 EnemyBattler**（敌人基类）。`Dog` 是这个类，`super` 是它的父类；
- `function Dog:init()`：定义 Dog 的 `init` 方法。**注意冒号**——冒号是 Lua 的语法糖：`Dog:init()` 等价于 `Dog.init(self)`，即"自动把对象自己作为第一个参数传进去"。所以方法里才能用 `self`；
- `super.init(self)`：先调用父类的 init——"先按基类的规矩初始化一遍"；
- `self:setActor("dog")`：`self` 就是这个对象本身（"我自己"）。`self:setActor("dog")` 就是"给我自己设置角色形象"；
- `self.max_health = 450`：给对象挂一个属性。**不需要提前声明**——直接赋值就存在了，这就是"表什么都能装"在对象上的体现。

读 Kristal 代码时的万能口诀：**冒号调方法，点号读属性，`self` 是自己，`super` 是爸爸**。

## 回调与游戏循环

游戏不是"从头到尾跑一遍"的——它是**每一帧都在跑**的循环。Kristal 的对象有几个关键的回调时机：

- `init()`：对象被创建时，初始化一次；
- `update(dt)`：每帧调用，dt 是这一帧经过的时间——"持续发生的事"都写在这里（移动、计时、检查碰撞）；
- `draw()`：每帧调用，负责画自己。

比如一个波次（wave）：创建时 `init` 设置参数，每帧 `update` 里让骨头移动、让计时器走，结束时交给框架收尾。你写的大部分代码，都是"在正确的回调里做正确的事"。

举个具体的："骨头从右往左飞"这个效果，拆开看就是——`init` 里记录起始位置和速度，`update` 里每帧把 x 坐标减掉"速度 × dt"，再检查一下是不是飞出了屏幕。几行代码，一个弹幕就动起来了。第 06 集我们会亲手写这个。

## 在战斗脚本中使用 Lua

把前面的概念映射到战斗上，一目了然：

- **敌人（EnemyBattler）**：一个类。`init` 里写数值和 ACT 选项，`onAct` 里写每个 ACT 的效果，`getAttackDamage` 里决定伤害怎么算（第 02 集见过）；
- **Encounter**：一个类。决定敌人是谁、回合怎么流转；
- **Wave**：一个类。`init` 定参数，`update` 让弹幕动起来——你看到的"骨头从右往左飞"，就是每帧 `update` 里改位置坐标的结果；
- **ACT 效果**：匿名函数或方法——"玩家选了讲笑话，就执行这一段"。

**每个文件都是一个类，每个类都是一张表，每个方法都是冒号函数**——记住这三句话，你就能读懂项目里 90% 的代码。

## 常见错误与阅读方法

新手最常踩的坑，按出现频率排：

- **拼写错误**：Lua 不会检查拼写，`self.max_hp` 和 `self.max_health` 是**两个不同的属性**——写错一个，游戏表现就"莫名奇妙"。好在 LuaLS（第 01 集配的编辑器补全）能帮你；
- **nil 错误**：访问不存在的字段返回 `nil`，nil 参与计算就报错。报错信息里会告诉你"attempt to index a nil value"——翻译：你访问了一个不存在的东西，往前查那个变量是谁；
- **忘了 `end`**：`if` 和 `for` 都要 `end` 收尾，少写一个就是语法错误；
- **索引从 0 开始**：`t[0]` 是 nil，别用别的语言的习惯。

看到报错别慌：先看它说**哪个文件第几行**，打开那行附近看看，八成是上面四种之一。

## 练习路线

学到这里，你已经具备"读得懂、改得动"的能力了。练习按这个阶梯来：

1. **改文本**：把敌人 check 文本换一句话（`Game:loc` 的 JSON 里改）；
2. **改数值**：把狗的 450 血量改成 9999（`self.max_health` 那行）；
3. **加小行为**：给 ACT 加一个新选项（抄现有 ACT 的写法，改名字和文本）；
4. **改逻辑**：让某回合的弹幕更快/更慢（改 wave 里的计时参数）。

每一步改完，`Ctrl+R` 热重载看效果（第 01 集教的）——这就是第 03 集说的"验证"。
