# EX00：Linux 与 Android Termux 开发环境（番外）

这是一篇**番外**——写给两类读者：正在用 Linux 的，和想在安卓上折腾的。

说句实在话：dr 社区里有不少年轻的朋友没有自己的电脑，安卓手机就是唯一的设备。这个系列的正篇默认了"你有台电脑"，对你们不太友好，所以有了这篇。但我提前说明：**Linux 环境 和 安卓环境 存在差异，但安卓上的折腾，几乎全是从 Linux 的思路出发的**——Termux 就是一个 Linux 环境，所以这两件事放在一起讲，省得你来回跳。

如果你是 Linux 桌面用户，这篇可以只看到"安卓"之前的部分；如果你只有手机，那建议从头看到尾——Linux 那部分你会用得上。

## 适合的使用场景

先分清两种场景，因为它们的气质完全不同：

**Linux 桌面**：和 Windows 一样的"正经开发环境"，只是换了一套工具链。它比 Windows 简洁得多——包管理器一条命令装好一切，环境变量之类的东西基本不用你碰（原因后面马上说）。第 01 集的全部内容，在 Linux 上都成立，而且更顺。

**安卓**：困难模式。手机/平板/移动设备不是为开发设计的，你走的每一步都是在和系统权限搏斗。能做，但你要有心理准备：这条路注定比电脑折腾。

所以我的建议很直白：**但凡你能搞到一台电脑（哪怕是便宜的二手），都优先用电脑**。手机方案是"没有选择时的选择"，不是"更好的选择"。

## 安装 love：Linux 比 Windows 简洁在哪

先说说 Linux 和 Windows 的一个根本差异：在 Windows 上，装任何软件都是"找安装包"——去官网或下载站，下载 exe，双击，一路下一步，每装一个软件都要重复一遍；而 Linux 完全不是这套，一条命令，包管理器把下载、安装、依赖、更新全包了。有人喜欢 Windows 那种"点点点就装好"的直观，有人喜欢 Linux 一条命令的爽快——见仁见智，但对我们开发来说，包管理器确实省事太多。（其实 Windows 现在也有包管理器，winget 之类，不过这不是本系列的重点，感兴趣的可以自己搜搜。）

第 01 集里，Windows 用户装了 love 之后还要手动配 PATH，折腾半天。Linux 上完全没有这一步——包管理器装完，`love` 命令直接就能用，环境变量它全给你配好了。

不同发行版，一条命令的事：

```bash
# Debian / Ubuntu 系
sudo apt install love

# Fedora / RHEL 系
sudo dnf install love

# Arch 系
sudo pacman -S love
```

装完验证一下：

```bash
love --version
```

看到类似 `LOVE 11.5 (Mysterious Mysteries)` 的输出就成了。

一个诚实的提醒：Debian 和 Ubuntu 官方仓库里的 love 版本可能偏旧（发行版仓库就是这样，求稳不求新）。Kristal v0.10 对应的是 LÖVE 11.5，版本差太多的话可能跑不动——如果 `love --version` 出来的版本明显低于 11.5，就去官网下载对应版本，或者找找社区维护的新版包。Fedora 和 Arch 的仓库版本都很新，不用担心。

另外，第 01 集里 Windows 专属的那些坑（Xbox 弹窗、中文路径抽风之类）在 Linux 上统统不存在——这也是 Linux 开发体验清爽的原因之一。

## 配置 Kristal 项目

这一步和第 01 集完全一样，而且比 Windows 顺：

```bash
git clone https://github.com/KristalTeam/Kristal
cd Kristal
git checkout v0.10.0
```

然后 thrash-machine 也一样——Use this template 创建你自己的仓库，克隆，然后**直接**跑初始化脚本：

```bash
./start.sh
```

注意，没有 Git Bash 那一堆事——Linux 的终端天生就是 bash，`./start.sh` 直接就能跑。这也是第 01 集里 Windows 用户折腾的 Git Bash，在这里根本不存在的原因。

至于 mods 目录：Linux 上它在 `~/.local/share/love/kristal/mods/`（也就是 `$XDG_DATA_HOME/love/kristal/mods/`）。和第 01 集一样，克隆的项目直接放这里，启动引擎后从项目列表选。嫌路径难记也没关系，引擎主菜单的"打开项目文件夹"按钮会直接带你过去。

## 使用编辑器开发

终端流的读者，我推荐两个编辑器：**Helix** 和 **Emacs**。（严格来说 Emacs 是个 GUI 软件，但它和 Helix 一样走键盘驱动的那套路子，也能在终端里跑，所以放在终端流一起讲。）别慌，这不是让你从零配环境——thrash-machine 克隆下来就自带它们的项目级配置（`.helix` 和 `.emacs` 目录，以子模块形式内置，克隆时一起拉下来了）。

以 Helix 为例，自带配置里按 `Space` 就能看到常用的快捷键：

- `Space f`：格式化当前文件；
- `Space o`：打开文件选择器；
- `Space l`：**一键启动**——它会在分离的终端窗口里，自动找到你的 Kristal 引擎，直接以 `love <引擎目录> --mod <你的项目id> --auto-mod-start` 启动你的项目，全程不用敲命令；
- `Space L`：同上，但终端保持打开，方便看 love 退出时的输出。

顺带一提，这个配置还带 LuaLS 的补全设置，`Game.` 的 API 补全一样有——和第 01 集 VSCode 里那个效果类似。

Emacs 的配置是同构的（`.emacs` 目录，快捷键和启动脚本都在），用 Emacs 的读者按 README 来就行。

喜欢 VSCode 的也没关系——第 01 集教的那套在 Linux 上照用不误，Kristal 扩展一样装。你要是眼馋 Helix 那些快捷键，也可以在 VSCode 里自定义键位绑到类似的功能上，效果差不多。

## 安卓：我知道你们需要，但这真的是困难模式

终于到正题了。先把话说在前面：**这条路的每一步都在和安卓的系统权限搏斗，没有电脑的用户，这是你们唯一的路，但也请做好折腾的心理准备。**

安卓上有两条路线，先分清它们的区别：

- **轻量路线：安卓 App 组合**。用 acode 写代码，用 love for android 跑游戏——不搞完整 Linux 环境，手机还是手机，只是多装了几个开发 App。轻、快、够用，是绝大多数人的选择。但你需要和 Android 的沙盒限制做一点搏斗。
- **重量路线：Termux 里的完整 Linux**。在手机上跑一个真正的 Linux 环境（proot/chroot），把手机变成"一台 Linux 电脑"，在里面用桌面式的工具链开发。完整、强大，但每一步都更折腾，性能也打折扣。

简单说：**轻量路线解决"能不能做"，重量路线解决"能不能做得像电脑一样"**。本文以轻量路线为主——先跑通，比什么都强。

另外实话实说：如果你没有安卓平板和键盘，光靠手机小屏幕，和虚拟键盘敲代码，开发过程真的非常折磨。搞个蓝牙键盘，或者 USB 转 Type-C 接一把有线键盘，配哪个都行——有条件的，弄个大平板，或者外接显示器——这大概是安卓开发里性价比最高的设备投资。

### 主工作流：acode 写代码 + love for android 跑游戏

两个工具：

- **acode**：一个安卓上的代码编辑器，支持语法高亮、终端、文件管理，写 Lua 够用。Google Play 或它的官网都能装。（当然，MT 管理器这类文件管理软件也自带文本编辑，硬要的话也能写代码——工具选择见仁见智，我只是推荐开发体验相对好一点的。）
- **love for android**：LÖVE 的安卓版。官方在 [love2d.org](https://love2d.org/) 的 [GitHub Releases](https://github.com/love2d/love/releases) 里提供了预构建的 APK（Android 版和桌面版同版本号，目前是 11.5）。装上之后，用文件管理器直接打开 `.love` 文件就能运行游戏。

acode 到手后，有几件小事可以顺手配一下：

1. **高亮**：不用配——acode 内置了 100 多种语言的语法高亮（基于 Ace Editor），打开 `.lua` 文件就能看到。
2. **主题**：设置 → 主题，Editor 主题管代码配色，App 主题管界面外观，挑个顺眼的。
3. **Lua 插件**：设置 → 插件，在插件商店里搜 Lua，有格式化之类的插件，装一个写代码更顺手。
4. **Kristal 补全**：想折腾的话，acode 插件市场里有个 **Lua Language Support** 插件（作者 Thraize，也叫 Acode Lua Language Client）——补全、跳转定义、重命名符号、错误诊断都有，是 acode 上最完整的 Lua 支持。它底层用的是 lua-language-server，而且 acode 自带内置 LSP（语言服务器——也就是给你语法诊断之类的东西）：装好插件后也可以走内置模式（设置里的 "Use Acode Built-in LSP" 开关），缺LSP时 acode 还会自动帮你装。配置 Kristal 补全走的是标准路子：在项目根目录放一个 `.luarc.json`，把 `workspace.library` 指向 Kristal 的 `luadoc_meta` 文件夹——和电脑上 VSCode 配的完全是同一套东西（见第 01 集）。折腾党可以试试，怕麻烦的先用基础高亮+格式化，完整的补全体验留到电脑上享受。

还有一个绕不开的问题：**CPU 架构**。手机和平板基本都是 ARM 架构，而电脑主流是 x86——这两个架构不互通。love for android 的 APK、Termux 的软件包，都是按 ARM 编译的，在正常手机上没问题；但如果你手头是 x86 的安卓设备（某些平板、安卓模拟器），就会碰到装不上或者跑不动的兼容问题。反过来，在 x86 电脑上跑安卓模拟器想运行 ARM 的包，也得靠兼容层，性能要打折扣。（顺带一说：LÖVE 本身是跨架构的——桌面版在 x86 和 ARM 的 Linux 上都能跑，安卓版本来就是 ARM 的。所以架构问题主要出在安卓特殊设备这个场景，电脑上不用操心。）所以：正常手机放心搞，特殊设备先查一下自己的架构。

最难的点在文件访问。这里得花点篇幅讲讲安卓那"屎山"一样的存储结构——有个大概印象就行：

安卓的存储是一层层叠出来的历史包袱。早年（Android 9 及以前），应用拿到权限后基本想放哪放哪，简单粗暴；后来出于安全问题，从 Android 10 开始引入万恶的"分区存储"，Android 11 强制实施——于是现在的局面是：每个应用都有自己的"沙盒"文件夹（`Android/data/<应用包名>/`），别的应用默认无权访问——导致你的文件管理器压根看不到这些文件夹！！data 文件夹成了各路应用互相看不见的格子间。文件管理器想读别人的格子，得申请特殊权限；厂商们（MIUI、鸿蒙这些）还在上面再叠一层自己的规则。这还不算完——应用私有数据、用户可见的公共目录、obb 目录，各有各的权限逻辑。

这套结构对我们折腾开发没有任何直观好处，纯粹是安全策略层层堆叠的产物，叫它屎山一点不冤。而好巧不巧，love for android 本来也不是为开发设计的——它只是为了让玩家在手机上测试**电脑上写好的游戏**：它可以读外部的 `.love` 文件，但不能直接啃源码，除非你把项目放进它的沙盒文件夹里。到这里，你应该能明白为什么文件访问这么弯弯绕了。解决方案分几档：

- **配合 Shizuku**：一个安卓上的"免 root 提权"工具，通过无线调试给应用授权，让文件管理类应用能访问受限目录。比 root 门槛低很多，是目前最推荐的辅助方案。
- **有 root 的设备**：直接搞，root 用户拥有全部权限，想怎么访问怎么访问。
- **都没有**：那就只能绕——比如在 love 能访问的目录里工作（像 `Download` 这类公共目录），然后用 acode 在两边倒腾文件。麻烦，但可行。

### Termux 路线：proot 和 chroot

如果你想要"真正的 Linux 环境"，可以在 [Termux](https://termux.dev/)（安卓上的终端模拟器，从 F-Droid 下载）里折腾——这就是为什么我说 Linux 是安卓折腾的基础：你在 Termux 里用的全是 Linux 的命令和工具。想深入的话，[Termux-Desktops](https://github.com/LinuxDroidMaster/Termux-Desktops) 这个仓库收集了在 Termux 里安装各种桌面环境和发行版的一键脚本与资料，是这条路上的宝藏。

Termux 里有两条路线，我都只做简单介绍，因为这条路很硬核：

- **proot**：用户态模拟根目录，不需要 root，装起来相对容易。缺点：性能可能不太好（模拟层开销），大型项目会明显吃力。参考资料：[Termux 官方 wiki 的 PRoot 页面](https://wiki.termux.com/wiki/PRoot)。
- **chroot**：真正的根目录切换，性能好得多。但要求设备已 root，配置也繁琐得多。参考资料：[Termux 官方 wiki 的 Chroot 页面](https://wiki.termux.com/wiki/Chroot)。

对绝大多数人，我的建议是：**别走 Termux 全环境路线**。在手机上调出完整 Linux + Kristal 的工作流，性能、输入、屏幕尺寸全都是坎。先用 acode + love for android 把"能写、能跑"的最小循环跑通，比什么都强。

顺带一提：在 Termux 里用 Git 操作项目，和 Linux 完全一样——`pkg install git` 装好，clone、push、pull 全套都有。具体的 Git 操作，我们留到番外 EX03（Git 与 GitHub 协作）再细讲。

## 与 Windows 工作流对照

最后把三条路摆一起说：

- **Windows**（第 01 集）：图形界面为主，路径和 PATH 是主要的坑，编辑器用 VSCode 最省心。
- **Linux**：终端为核心，包管理器解决安装，几乎没有 PATH 的烦恼，编辑器 Helix/Emacs/VSCode 任选。
- **安卓**：一切靠凑——文件访问要抢权限，编辑器用手机应用，跑游戏靠 love for android。能跑，但永远是"克服困难"而不是"顺手"。

文件管理、命令行、编辑器，三条路各有各的差异，但底层的东西完全一样：Git 克隆、love 启动、Kristal 加载项目。**核心概念学会了，换平台只是换皮。**
