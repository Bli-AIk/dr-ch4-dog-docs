# 第 01 集：Windows 开发环境搭建（VSCode）

你好呀。这是《从零做一个 Deltarune 同人游戏》系列的第 1 集。

上一集，我们认识了 Kristal 引擎，也知道了这个系列要做什么。这一集没有代码，我们专心把地基打好：让 LÖVE、Kristal 和你的第一个项目，在 Windows 上全部跑起来。

## 先说清楚

你用的系统是 Windows，对吧？好，这集就是为你准备的（Linux 和 Android 的读者，请移步番外 EX00——但建议你们先看完这集，因为这集的内容会覆盖绝大部分基础环境配置）。

本集结束时，你会拥有一个可以运行的开发环境：一个命令行就能启动的 LÖVE 和 Kristal，一个能在项目列表里点开的游戏，以及一个配置好的 VSCode。之后每一集，我们都在这个环境上开工。

## 要准备的工具

其实没几样。整个开发链只有四个东西：

- **Git**：用来下载 Kristal 源码和项目模板。**强烈建议**安装，这个系列里你只需要会用 `git clone`（更多 Git 知识可以看番外 EX03）。实在装不上/下载太慢的话，GitHub 上每个仓库都提供 Download ZIP，下载解压一样能用——只是以后更新要重新手动下载一遍。
- **LÖVE 11.5**：Kristal 的运行时——就是第 00 集说的那块"地基"。游戏最终就是靠它跑起来的。
- **Kristal 源码**：引擎本体。开发同人游戏要用源码版，为什么下面会说。
- **VSCode**：代码编辑器。官方 wiki 里也明确推荐用它，而且 Kristal 有官方扩展，后面会装。

这四样工具（外加 Kristal 本体），**Kristal 中文交流群**（群号：1062361876）里都备了现成的安装包——官方渠道下载太慢、或者怎么都装不上的时候，来群里直接拿。群里的宝库不止这些，后面还会再提到。

## 安装 LÖVE，并配置环境变量

先去 [love2d.org](https://love2d.org/) 下载 Windows 安装包，一路下一步装完。默认位置是 `C:\Program Files\LOVE\`。

装完先别急着用。LÖVE 的 Windows 安装包**不会**自动把程序目录加进 PATH——也就是说，你在命令行里输入 `love`，系统根本不知道你在说什么。所以接下来这步要手动来——**强烈建议不要跳过**：整个系列的命令都默认 `love` 可以直接用，现在花两分钟配好，后面能省下无数困惑（实在嫌麻烦的话，后文的启动脚本也能用绝对路径绕过它，但那是下策）：

1. 按 `Win` 键，搜索"编辑环境变量"，打开（控制面板里的"系统属性 → 环境变量"也行）。
2. 在"用户变量"里找到 `Path`，双击编辑。
3. 点"新建"，填入 `C:\Program Files\LOVE`，一路确定保存。
4. **新开一个** cmd 窗口（旧窗口不会刷新 PATH），输入：

```cmd
love --version
```

能看到返回 `11.5` 这样的版本号，就说明成了。这一步很重要，因为后面启动 Kristal 全靠 `love` 命令——如果 PATH 没配好，这个命令就永远跑不起来。

## 配置 Kristal：为什么是源码版

官方 wiki 把 Kristal 的获取方式分成三种：

- **公开测试版（Beta）**：官方不推荐。更新太慢，容易过时。
- **每日构建版（Nightly）**：推荐给**玩**同人游戏的玩家，每次代码变更都会重新构建，最新但未经测试。
- **源代码**：推荐给**做**同人游戏的开发者。最麻烦，但可控性最强，以后想改引擎、想参与开发都靠它。

不过有一点我要和 wiki 唱个反调：wiki 默认推荐"最好用最新版"，但那是站在**玩家**和**追新的开发者**角度说的。**对于教程、以及需要长期维护的库来说，我强烈建议锁定版本**——Kristal 的 API 一直在变动，跟着最新版走，你的项目随时可能因为引擎改了接口而突然报错，教程里的代码也会对不上。wiki 说 Beta 版"容易过时"，但对我们来说，过时反而是好事：API 定了，社区库也都兼容它。每日构建版（版本号还没到 v0.11）确实做了很多很棒的更新，比如第四章的攀爬机制——但为了稳定，这个系列的项目（Dog Battle、Thrash Machine 模板）都基于 **v0.10**（beta 版），mod.json 里的 `engineVer` 写的也是 `v0.10.0`。

我们要做游戏，所以用第三种——但要锁到 v0.10.0。在你想放引擎的目录打开终端：

```cmd
git clone https://github.com/KristalTeam/Kristal
cd Kristal
git checkout v0.10.0
```

`git clone` 默认拉的是 main——引擎的每日开发版。所以我们要用 `git checkout v0.10.0` 切到本系列锁定的版本。以后想追新，`git pull` 之后再 checkout 新 tag 就行。

没有 Git 的读者：注意**别直接**用仓库页的 Code → Download ZIP——那是 main 的最新开发版，版本会对不上。要去仓库的 **Releases** 页面，找到 v0.10.0，展开它的 Assets，里面能看到几种东西：

- **Source code (zip)**：源码，和我们 git 方式拿到的一模一样。
- **打包好的本体**：Windows 上是一个可以直接运行的 exe 版本，其他平台则是 .love 文件，双击或用 LÖVE 打开就能玩。打包版省事，但它是"成品"——不方便改源码，而本系列后面可能要看引擎源码、甚至动手改引擎，所以还是推荐用源码版。

下载 Source code (zip)，解压后，在终端里 `cd` 进解压出来的文件夹。

然后，运行：

```cmd
love .
```

Kristal 主菜单应该就出现了。第一次看到它，可以随便逛逛——在主菜单里找到项目列表的入口，点进去，你会看到一个项目列表。

## 标准方式：用引擎本体创建项目

这是官方推荐的标准流程：**运行引擎本体，在游戏里创建项目**。

在刚才的项目列表底部，有一个"创建新项目"按钮。点它，你可以配置项目名称、项目描述、基于 Deltarune 的哪个章节，以及各章节间的功能开关。随便填一个名字，创建。

创建出来的项目会出现在列表里，点一下就能运行。项目文件存在哪？主菜单里有一个"打开项目文件夹"的选项——点它，资源管理器会打开 mods 目录（源代码版在 `C:\Users\<你的用户名>\AppData\Roaming\LOVE\Kristal\mods\`）。以后你下载、克隆的项目，都放进这个文件夹；放进去的每个文件夹就是一个独立项目。

如果你下载了源码版的 Kristal，你也可以把 mods 放到 `Kristal\mods` 下。这样也许更好找一些。

> 📷 此处插入截图：创建新项目界面 / 项目列表中出现新项目

创建出来的项目里有什么？打开文件夹看看：`mod.json`（项目配置：名称、章节、初始队伍、物品……）、`mod.lua`（项目代码入口）、`assets/`（素材）、`scripts/`（代码）。别急着看懂，第 04 集会一个一个讲。

## 我们的路径：用一台现成的揍人机！

好了，坦白一下：上面那套标准流程，是官方推荐的做法。但我实际起步用的，并不是它。我用的是自己维护的一个预设模板：[Thrash Machine](https://github.com/Bli-AIk/thrash-machine)。（我叫它揍人机，因为这玩意儿就跟 dr 的揍人机一样是东拼西凑的，难绷）

它和引擎自带的创建方式差别在哪？自带的创建会给你一个非常朴素的空项目；而 Thrash Machine 是一个打包好的起点，默认就带了一些国内开发者会惦记的东西：

- **kristal-i18n 本地化库**：中英文语言文件、游戏内切换语言的设置菜单，开箱即用；
- 完全汉化的模板文本——基于好人汉化组文本制作；
- 开发期调试工具（能够连接vscode终端调试的控制台、以及战斗启动参数）、仿blender快捷键的debug小工具，等一堆预设；
- Android 虚拟按键库（感谢zzy_10o！！我是在ta写的库的基础上改的）；
- 整包构建脚本。包含 Win，其他平台（.love文件），以及 Android。

用起来也稍微多两步——因为 Thrash Machine 是一个 GitHub **模板仓库**，正确姿势是先克隆**你自己的那一份**：

1. 打开 [Thrash Machine](https://github.com/Bli-AIk/thrash-machine) 仓库页，点绿色的 **Use this template** 按钮，创建你自己的仓库（名字随便起，比如 `my-first-kristal-game`）。
2. 克隆**你自己**的仓库到项目文件夹（就是刚才说的 mods 目录，地址换成你自己的）：

```cmd
git clone --recurse-submodules https://github.com/<你的用户名>/my-first-kristal-game.git
```

3. 进入目录，运行初始化脚本——它会把项目名、Mod ID 这类模板占位内容一次性替换成你的项目名，并拉齐所有子模块：

```cmd
cd my-first-kristal-game
./start.sh
```

（`start.sh` 是 bash 脚本，在 **Git Bash** 里运行——装 Git for Windows 的时候会自带 Git Bash，在文件夹里右键 → "Git Bash Here" 就能打开。）

（另外我需要坦言：作者本人没在 Windows 上实测过 `start.sh`——理论上一整套依赖 Git for Windows 全自带，语法也没问题，但万一你遇到行尾、权限之类的怪问题，欢迎反馈，我看到会修复。）

（zip 下载也可以，但它带子模块——libraries 目录里的库是独立的仓库，**zip 不会把它们带进来**，所以这个项目更推荐用 Git 克隆。如果您实在无法使用 git，可以来我们的群里看看）

初始化完成后，回到 Kristal，项目列表刷新一下，你的项目应该就出现了（名字是你起的那一个）。点进去，跑起来：

## 配置 VSCode

编辑器这一步，官方 wiki 的推荐是 VSCode + 官方扩展，我们照做。

1. 安装 [VSCode](https://code.visualstudio.com/)（安装时建议勾上"添加到 PATH"和"通过 Code 打开"）。
2. 打开扩展面板，搜索 **Kristal**，安装官方扩展（marketplace ID：`kristal.kristal-vscode`）。它是基于 Lua 语言服务器（LuaLS）做的，打开项目时会提示你"是否启用 Kristal 环境"——确认就行。
3. 用 VSCode 打开你的项目文件夹。第一次打开会问"是否信任此文件夹的作者"——这是你的项目，你就是作者，点信任。
4. 现在打开任意 `.lua` 文件，试试输入 `Game.`——应该有 API 补全弹出来。

> 📷 此处插入截图：VSCode 里 Game. 的补全效果

如果扩展没有生效（比如提示没弹出来）：手动安装 Lua 扩展（搜索 Lua，作者是 sumneko，就是 LuaLS 本体），然后在项目设置（`.vscode/settings.json`）里，把 `Lua.workspace.library` 指向你克隆的 Kristal 目录下的 `luadoc_meta` 文件夹，也能得到一样的补全。

## 日常工作流

环境搭好了，之后的日常循环其实就三步：

1. 在 VSCode 里改代码；
2. 启动 Kristal——在**引擎目录**运行 `love .`（注意：不是项目目录！项目是跑在 Kristal 里的，你没法单独 `love .` 一个项目来启动它），然后在项目列表里点开你的项目；
3. 看效果，不满意回到第 1 步。

每次都要开终端敲命令，有点烦？**强烈建议**做一个一键启动脚本——后面整个系列的开发，基本都是双击它启动的：在喜欢的地方建一个 `run-kristal.bat`，写上下面内容（把两处路径换成你自己的）：

```bat
"C:\Program Files\LOVE\love.exe" "C:\你的\Kristal目录"
```

以后双击它就能启动 Kristal。（如果你配好了 PATH，第一行也可以简写成 `love`，这就是上面强烈建议你们配 PATH 的原因。）注意每个人的路径都不一样，这个文件只属于你自己，建议不要提交到项目里。

说到启动，这里得提一提 Lua 的魔法：**热重载**。你没必要改一下代码就反反复复重开游戏——开发模式下，游戏运行中按 `Ctrl+R` / `Ctrl+Shift+R`，Kristal 会快速保存（按shift则不保存，就和直接重开游戏一样）并重新加载项目，改完代码不用重启引擎，按一下立刻生效。这也是 Kristal 和其他游戏引擎最大的不同之一：原生的热重载，改完立刻看到效果，开发循环快得离谱。

当然，魔法是有前提的——前提是别写出 bug。要是写出了能把游戏干崩的 bug（比如引用了不存在的对象），热重载也救不了你，老老实实重开吧。

## 常见问题

按经验列几个新手最容易踩的坑：

- **`love` 不是内部或外部命令**：PATH 没配好，或者终端窗口没重新开。重新配置后开新窗口再试。
- **中文用户名/路径**：Windows 上如果用户名，路径带中文，某些工具链偶尔会抽风。能避免就避免，尽量只用ASCII字符（即英文字符，数字，下划线等等）。
- **用 love 命令启动游戏，弹出莫名其妙的"你想如何打开此文件？"**：Windows 的 Xbox 相关设置（主要是 Xbox Game Bar）有时会捣乱，把设置 → 游戏 → Xbox Game Bar 关掉就好。这弹窗跟你的操作没关系，别慌。
- **项目不出现在列表里**：确认它直接放在 mods 目录下，且**没有**套在多余的文件夹里（比如把解压出来后是文件夹套文件夹——那你就需要挪出来）。
- **版本对不上**：项目 `mod.json` 里有 `engineVer` 字段，比如 `v0.10.0`，要和你的引擎版本匹配。启动引擎时可以在左下角看到版本号；若引擎更新了大版本，旧项目可能出 bug。
