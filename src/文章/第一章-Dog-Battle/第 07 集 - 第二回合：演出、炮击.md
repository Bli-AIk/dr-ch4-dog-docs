## 开头演出：转圈、变白、吸收粒子

先看狗在动画里干了什么：

变白——白色覆盖整个狗；

这一段是纯演出，就是把气氛顶上去。

我们给这个回合起名叫 `gb`（好吧，也许你可以起一个更正式点的名字……不要混淆了，这里的`gb` 是我们自己起的回合名，不是弹幕！）。

先看整段演出的"指挥"——`scripts/battle/waves/gb.lua` 的 onStart：

```lua
-- ……（gb.lua 开头的常量先省略——SPIN_TIME、SPIN_LOOPS 这些，用到时再讲）……

-- 我们定义一个局部方法，循环播放 spin 动画，loops_left 次
-- 递归：播完一次还有次数（loops_left > 1），就再播一次；全部转完，调 callback() 把流程交出去
-- callback：一个"等会儿再调用的函数"——Lua 里 *函数可以当参数传*，先存着，到时候再调用
-- 转完该干嘛由调用方决定——你看到时候这个函数咋用的，就明白了
local function playSpin(battler, loops_left, callback)
    battler:setAnimation({ "spin/spin", 1 / FPS, false }, function()
        if loops_left > 1 then
            playSpin(battler, loops_left - 1, callback)
        else
            callback()  -- 最后一圈转完：调 callback，进入下一段流程
        end
    end)
end

-- ……（中间还有 pickGBTarget、spawnCircle、spawnEye、spawnBlaster，以及文件末尾的 onEnd——讲到再贴）……

function GB:onStart()
    Assets.playSound("snd_knight_stretch", 1, 0.75)  -- 开头播放音效起手

    local attackers = self:getAttackers()
    self.dog = attackers[1]

    -- 记下开打前每人的血量——回合结束时要和它对比，看谁被轰到了（第 08 集讲）
    self.party_health = {}
    for _, battler in ipairs(Game.battle.party) do
        self.party_health[battler.chara.id] = battler.chara:getHealth()
    end

    -- 兜底：万一没有狗，就跳过演出直接开炮
    -- 正常情况下，这个波次是跟着狗走的；但调试时可能被单独拉出来跑——self.dog 会是空的
    -- 空的 self.dog 一用就崩，所以先检查一下
    if not self.dog then
        self:spawnBlaster()
        return
    end

    -- 加权随机挑一个 *攻击目标*（炮击节讲）
    self.dog.current_target = pickGBTarget()

    -- 蓝色雾气圆环先铺开
    self:spawnCircle()
    -- 白色覆盖（ColorMaskFX）：amount 从 0 缓动到 1，狗渐渐变白
    self.white_fx = self.dog:addFX(ColorMaskFX({1, 1, 1}, 0), "gb_white")
    self.timer:tween(SPIN_TIME * (SPIN_LOOPS - 1) / SPIN_LOOPS, self.white_fx, {amount = 1}, "linear")
    -- 开始从周围吸收白色粒子
    self:spawnParticle()
    self.particle_spawn_timer = self:getParticleSpawnInterval()
    -- 转圈快结束时，中央矩形收缩——把"吸力"聚焦成一条线
    self.timer:after(SPIN_TIME - CENTER_RECTANGLE_TIME, function()
        if self.dog then
            self:spawnCenterRectangle()
        end
    end)

    -- 转满 3 圈后依次：放音效 → 睁眼 → 复制体放大淡出 → 发射 GB
    playSpin(self.dog, SPIN_LOOPS, function()
        Assets.playSound("snd_dogresidue")
        self:spawnEye()
        self:spawnDogFlash()
        self:spawnBlaster()
    end)
end
```

`playSpin` 是递归播放：播完一次还有次数就再播，转完最后一圈把流程交给 `callback`——它为什么这么写、每步在干嘛，注释里都写全了，对着看就行。

顺带认识一下上面代码里的 `ColorMaskFX`——它是引擎"绘制特效"（DrawFX）家族的一员。作用：给对象的贴图**叠一层颜色**，`amount` 是强度——0 完全没效果（透明），1 纯色。我们这里 `ColorMaskFX({1, 1, 1}, 0)` 是"叠一层白色、先设为 0"，挂上之后走 tween 变到 1，狗就渐渐变白；发炮时还会再闪一下然后淡出、之后我们再把它“摘掉”（见后面炮击的那段代码）。

整体流程是：**addFX 挂上去 → 利用 tween 调参数 → removeFX 摘下来**（addFX 的第二个参数是给它起的名字，摘的时候按名字找）。

这个家族还有不少常用成员：`AlphaFX`（透明度，淡入淡出）、`RecolorFX`（整体重新着色）、`OutlineFX`（描边）、`ShadowFX`（投影）、`Gradient`（渐变）、`MaskFX`（遮罩）——全是"挂上去、调参数、摘下来"同一个路数，只是参数不同。各自的参数说明在 Kristal Wiki / API Reference 里搜 DrawFX 就有。

然后看雾气——但在看代码之前，得先认识一个概念：**shader（着色器）**。

看到原动画的那个雾效，你可能会懵："这到底咋做的？？"——说实在的，这真的可能是新手最摸不到头脑的部分。

我们需要编写一个 **shader** 来实现它。shader 本身是个很进阶、也很独立的领域——它不算游戏逻辑，更偏向"技术美术"（用代码做视觉效果）。想深入的话可以自己学，本教程里我们只"利用"，不"深究"：入门教材推荐《The Book of Shaders》（中文版：https://thebookofshaders.com/?lan=ch），还有 Shadertoy（https://www.shadertoy.com/）——海量现成 shader，可以白嫖、可以拆解。

如果你真的想系统性学习技术美术（为了你的游戏有吊炸天的特效！炫酷的后处理！超赞的光效！各种乱七八糟的视觉效果——），可以去看看 GAMES101、图形学、渲染，或者一系列相关的课程，然后尝试用 OpenGL 或者 Vulkan 手撕一个三角形！！！！——然后你就发现靠我怎么已经拐这么老远了，渲染这块害人不浅啊……你们当我啥都没说吧还是。

但为了让你们……多少知道这到底是怎么实现的，我还是简单拆一下原理，能理解就理解，理解不了拉倒：shader 是一个跑在显卡上的小程序。平时绘制是"贴图是什么颜色就画什么颜色"；套上 shader 之后，每个像素的颜色都要先交给它算一遍。我们这团雾，就是每个像素都被一段"迷雾算法"处理过：用噪声（一种随机又连续的数学函数）算出雾的浓淡，两层噪声叠起来、由 time 驱动着滚动——雾就"动"起来了，而且是那种飘忽不定的动。原理就这么多，够用了。

上面说的噪声、滚动，全在这个文件里——`assets/shaders/gb_mist.glsl` 全文（注释是后加的，帮你对应着看）。看不懂也没关系：这里看不懂，你就抄就行了，不影响后面：

```glsl
// 从 Lua 传来的两个参数（extern = 外部变量）
extern float time;
extern float white_amount;

// hash：把坐标"搅"成一个看似随机、但永远确定的数
float hash(vec2 p) {
    return fract(sin(dot(p, vec2(127.1, 311.7))) * 43758.5453);
}

// noise：把 hash 结果平滑连接——随机但连续，不会跳变
float noise(vec2 p) {
    vec2 cell = floor(p);        // 整数部分：落在哪个格子里
    vec2 local = fract(p);       // 小数部分：格子内的偏移
    local = local * local * (3.0 - 2.0 * local);  // 平滑插值的缓动

    // 四个角各取一个随机数，按偏移混合——格子之间无缝衔接
    float bottom = mix(hash(cell), hash(cell + vec2(1.0, 0.0)), local.x);
    float top = mix(hash(cell + vec2(0.0, 1.0)), hash(cell + vec2(1.0, 1.0)), local.x);
    return mix(bottom, top, local.y);
}

// effect：每个像素都会执行一次——会根据像素位置、noise等等的不同来计算颜色，然后返回这个像素最终的颜色
vec4 effect(vec4 color, Image tex, vec2 uv, vec2 screen_coords) {
    vec2 position = screen_coords * 0.012;          // 坐标缩放，雾的"颗粒"变肉眼可见
    vec2 scroll = vec2(time * 0.70, time * 0.34);   // 随时间滚动，两轴速度不同，飘得更自然
    float mist = noise(position + scroll);          // 第一层噪声 = 雾的浓淡
    mist = mix(mist, noise(position * 2.1 - scroll * 0.65), 0.45);  // 再叠一层更细的、反方向滚的噪声
    mist = smoothstep(0.18, 0.88, mist);            // 压对比度：浓的更浓、淡的更淡，雾"成型"

    // 按浓淡在深蓝 ↔ 雾蓝之间取色
    vec3 dark_blue = vec3(0.008, 0.025, 0.10);
    vec3 mist_blue = vec3(0.025, 0.10, 0.30);
    vec3 mist_color = mix(dark_blue, mist_blue, mist);
    // white_amount 越大越白——狗变白那段，雾跟着变亮
    vec3 output_color = mix(mist_color, vec3(1.0), clamp(white_amount, 0.0, 1.0));

    return vec4(output_color, color.a);  // 透明度保持不变
}
```


概念就位，再看圆是怎么把这团雾"套"上去的——GBCircle。它是 Kristal 椭圆物体 `Ellipse` 的子类：圆形是引擎现成的，shader 用引擎自带的 `ShaderFX` 挂上去：

```lua
local GBCircle, circle_super = Class(Ellipse)

function GBCircle:init(x, y, radius)
    circle_super.init(self, x, y, radius, radius)  -- Ellipse 的 init 收半径 rx、ry

    self.radius = radius
    self.alpha = 0
    self.white_amount = 0
    self.time = 0
    -- 挂迷雾 shader：ShaderFX 是引擎自带的"给物体上 shader"特效
    -- vars 里的函数每帧求值，把 time、white_amount 送进 shader
    self:addFX(ShaderFX("gb_mist", {
        time = function() return self.time end,
        white_amount = function() return self.white_amount end,
    }))
end

function GBCircle:update()
    circle_super.update(self)
    -- radius 被外面 tween 驱动，这里同步成椭圆实际大小
    self:setSize(self.radius * 2, self.radius * 2)
    -- time 每帧累加——shader 里雾的滚动就靠它
    self.time = self.time + DT
end
```

`Class(Ellipse)`——圆本身不用画了，直接用引擎的椭圆物体：`Ellipse(x, y, rx, ry)` 收半径，自带居中锚点，`self.alpha` 会被引擎的颜色管线自动应用（所以透明度 tween 直接生效，不用手动 setColor）。shader 用 `ShaderFX` 挂：`addFX` 是 ColorMaskFX 那课见过的套路——`ShaderFX("gb_mist", ...)` 从资产表取 shader（引擎启动时预编译好的），`vars` 里的函数每帧求值送进 uniform，雾就动起来了。想改雾的形状、颜色，改那个 `.glsl` 文件就行。

顺带一个注意点：这整段雾效用的全是引擎自带的能力——圆形是 `Ellipse` 物体，shader 走 `ShaderFX` 特效（内部从资产表取预编译好的实例，应用与恢复由引擎自己处理），透明度走 `self.alpha` 颜色管线。Kristal 的规矩是"物体 + 绘制特效"的组合：想给对象上色、描边、上 shader，先看 DrawFX 家族有没有现成的（ColorMaskFX、ShaderFX……）。shader 文件记得放 `assets/shaders/`、扩展名必须是 `.glsl`——引擎启动时预编译校验，编译失败会直接报出来。

然后是"吸收粒子"——为什么叫"吸收"？因为粒子是从周围**飞向中心**的。GBParticle：

```lua
local GBParticle, particle_super = Class(Ellipse)

function GBParticle:init(x, y, target_x, target_y, radius, travel_time)
    particle_super.init(self, x, y, radius, radius)  -- Ellipse 收半径 rx、ry

    self.start_x = x            -- 起点（圆环边缘）
    self.start_y = y
    self.target_x = target_x    -- 终点（圆心）
    self.target_y = target_y
    self.radius = radius        -- 粒子大小
    self.travel_time = travel_time  -- 飞完全程的时间（秒）
    self.progress = 0           -- 飞行进度 0~1，每帧推进
    self.layer = 1
end

function GBParticle:update()
    particle_super.update(self)

    -- 按飞行时间推进进度
    self.progress = self.progress + DT / self.travel_time
    local progress = math.min(self.progress, 1)
    -- 缓动（ease-out-cubic）：开头快、收尾慢，像被吸过去
    local eased_progress = 1 - (1 - progress) ^ 3

    -- 在起点和终点之间，按缓动后的进度插值
    self.x = self.start_x + (self.target_x - self.start_x) * eased_progress
    self.y = self.start_y + (self.target_y - self.start_y) * eased_progress

    if self.progress >= 1 then
        self:remove()  -- 飞到圆心就消失
    end
end
```

三个变量：起点、终点（圆心）、飞行时间。每帧按缓动推进进度，到点就 `remove()`。关键在缓动：`1 - (1 - progress) ^ 3`——ease-out-cubic（第 06 集 easings.net 那课说过的"演出用缓动"）：开头快、收尾慢，像被吸过去。粒子也是 `Ellipse` 子类——连 draw 都不用写，白色圆点引擎自己画（默认白、不透明）。

粒子本身不会"自己冒出来"——谁在生成它、多久生成一个，都是波次管着的。看下面这段（注释写全了；看之前先说个关键点：粒子出生在**圆环边缘**、飞向圆心——这就是"吸收"的起点和落点）：

```lua

-- 生成一个粒子：在圆环边缘随机位置出生，飞向圆心
function GB:spawnParticle()
    if not self.circle or self.circle.radius <= 0 then
        return  -- 圆没了就不生了
    end

    -- 角度随机（0~360°）——粒子散布在圆环一圈
    local angle = love.math.random() * math.pi * 2
    -- 大小也随机——错落有致，不是清一色的点
    local radius = PARTICLE_MIN_RADIUS
        + love.math.random() * (PARTICLE_MAX_RADIUS - PARTICLE_MIN_RADIUS)
    -- 出生点：圆环边缘（稍微往内缩一点，不贴边）
    local spawn_radius = math.max(self.circle.radius - radius * 0.25, 0)
    local center_x, center_y = self.circle.x, self.circle.y
    local x = center_x + math.cos(angle) * spawn_radius
    local y = center_y + math.sin(angle) * spawn_radius
    -- 飞行时间也随机——有快有慢，更自然
    local travel_time = PARTICLE_MIN_TRAVEL_TIME
        + love.math.random() * (PARTICLE_MAX_TRAVEL_TIME - PARTICLE_MIN_TRAVEL_TIME)

    local particle = GBParticle(x, y, center_x, center_y, radius, travel_time)
    particle.layer = self.circle.layer + 0.1  -- 画在雾气上面一层
    self:spawnObject(particle)
end

-- 生成间隔：偏大的间隔更常出现——多数时候慢慢来，偶尔连发，不会"均匀得假"
function GB:getParticleSpawnInterval()
    local bias = math.sqrt(love.math.random())
    return PARTICLE_MIN_SPAWN_INTERVAL
        + bias * (PARTICLE_MAX_SPAWN_INTERVAL - PARTICLE_MIN_SPAWN_INTERVAL)
end

-- 每帧倒计时，到点就生成一个粒子
function GB:update()
    super.update(self)

    if not self.particle_spawn_timer then
        return
    end

    -- 白闪到顶、或圆没了，粒子收工
    if not self.circle or not self.white_fx or self.white_fx.amount >= 1 then
        self.particle_spawn_timer = nil
        return
    end

    self.particle_spawn_timer = self.particle_spawn_timer - DT
    -- 一帧里可能攒了好几个间隔：一次全补上
    while self.particle_spawn_timer <= 0 do
        self:spawnParticle()
        self.particle_spawn_timer = self.particle_spawn_timer + self:getParticleSpawnInterval()
    end
end
```

## 制作炮击攻击：先找轮子

炮击——GB（Gaster Blaster）。

这一节先坦白：我们最初的 GB 是**手搓的**——自己写子弹类、自己画光柱……然后效果还不咋地。

后来在社区发现一个现成的库 `gaster_blaster`（v0.0.1，作者 Scarm、JustAnotherRandomUser、Toby Fox），就把手搓版换了——手感、动画都比自己写的强。这就是 EX05 会提到的"先找轮子"：写完才发现有现成的，下次还是得先搜（呜呜呜）。

装库很简单：把库文件夹放进项目的 `libraries/` 目录。引擎启动时扫描 `libraries/` 下的每个子目录，解析里面的 `lib.json`（库的"身份证"，id 是 `gaster_blaster`），注册进项目；库的脚本会被自动挂载——`scripts/battle/bullets/` 下的文件按文件名注册成子弹 ID。装完库，`spawnBullet("gaster_blaster", ...)` 就能用了。

库自带一个测试波次 `gb_test.lua`（47 行），等于官方 API 手册——`spawnBullet` 的全部参数一目了然：

```lua
---@class GBTest : Wave
local GBTest, super = Class(Wave)

function GBTest:init()
    super.init(self)
    self.time = 8  -- 这个波次总共跑 8 秒
end

function GBTest:onStart()
    local arena = Game.battle.arena
    local center_x, center_y = arena:getCenter()  -- 战斗框中心
    local arena_top = arena:getTop()
    local arena_right = arena:getRight()

    -- A vertical shot from above. The beam stays active long enough to show
    -- both frame damage and repeated graze TP.
    -- 翻译：一发从正上方打来的竖炮；光束持续够久，能同时看到帧伤和反复擦弹攒 TP。
    self:spawnBullet(
        "gaster_blaster",  -- 库的子弹 ID（按文件名注册的）
        center_x,          -- 生成位置 x
        arena_top - 80,    -- 生成位置 y：战斗框上方 80 像素，从外面滑进来
        0,                 -- rot：旋转角（度）——第一发 0，竖直
        center_x,          -- target_x：滑向的目标位置
        arena_top + 18,    -- target_y
        0,                 -- target_rot：目标角度
        45,                -- wait_time：到位后等待 45 帧再开火
        45,                -- blast_time：光束持续 45 帧
        true               -- play_sound：带发射音效
    )

    -- Follow with a horizontal shot to demonstrate rotation and exit motion.
    -- 翻译：再补一发横炮，演示旋转角度和"打穿后继续滑出"的出场方式。
    self.timer:after(2.5, function()  -- 2.5 秒后再来一发
        self:spawnBullet(
            "gaster_blaster",
            arena_right + 80,  -- 从战斗框右侧外面滑入
            center_y,
            90,                -- rot：第二发 90，横着打
            arena_right - 18,  -- 目标位置：滑到战斗框内
            center_y,
            90,                -- target_rot：保持横着
            45,
            45,
            true
        )
    end)
end

return GBTest
```

九个参数都标在注释里了，照着对一遍就懂。唯一值得单拎出来的：`rot` 和 `target_rot` 传的是**角度**，不是弧度——库内部自己转的。

gb_test 是库的"默认用法"；我们的 gb.lua 玩得更进阶——**把库的进场接管过来**。看 spawnBlaster：

```lua
function GB:spawnBlaster()
    local arena = Game.battle.arena
    local center_x = arena:getCenter()      -- 战斗框中心 x
    local top_y = arena:getTop() + 18       -- 光束最终要停的位置
    local start_y = -120                    -- 起点：屏幕上方外面
    local final_y = top_y - 50              -- 终点：停位再往上 50 像素（滑入的落点）

    local bullet = self:spawnBullet(
        "gaster_blaster",                   -- 库的子弹 ID
        center_x,
        start_y,
        90,                                 -- 起始朝向 90°：滑入过程中缓动转到 0°，自带甩入感
        center_x,
        start_y,
        0,
        math.huge,                          -- wait_time 设成无限：进场由下面的 tween 接管，到位才设等待
        BLAST_TIME,                         -- blast_time：光束持续 45 帧
        true
    )
    bullet.damage = BLAST_DAMAGE            -- 覆盖库默认：66 伤害（库默认 damage = nil，没伤害）
    bullet.inv_timer = BLAST_INVULN_TIME    -- 覆盖库默认：每 0.2 秒结算一次伤害（帧伤思路）

    -- Skip the library's linear approach and let the wave own the entry
    -- motion. The final point stays above the arena's top position.
    -- 翻译：跳过库自带的"线性滑向目标"，进场演出由波次自己接管。
    bullet.state = 1                        -- 把库子弹直接拨到"等待发射"状态，不走它的 state 0 滑入
    bullet.target_x = center_x
    bullet.target_y = start_y
    bullet.target_rot = 0

    -- 用缓动让 GB 从屏幕上方优雅滑下来（1 秒，out-cubic）
    self.timer:tween(
        ENTRY_TIME,
        bullet,
        {y = final_y, rotation = 0},
        "out-cubic",
        function()
            bullet.wait_time = WAIT_FRAMES  -- 滑到位才设等待帧数（15 帧），开始蓄力
        end
    )

    if self.dog then
        self.dog:setAnimation("idle")       -- 狗回到待机动画
    end

    -- 白色覆盖闪到最亮，再淡出摘掉（狗变白的高潮收尾）
    if self.white_fx then
        local white_fx = self.white_fx
        white_fx.amount = 1
        self.timer:tween(
            WHITE_FADE_TIME,
            white_fx,
            {amount = 0},
            "out-cubic",
            function()
                if self.dog and white_fx.parent == self.dog then
                    self.dog:removeFX(white_fx)   -- 淡完摘掉特效
                end
                if self.white_fx == white_fx then
                    self.white_fx = nil
                end
            end
        )
    end
end
```

注释里把每个参数和覆盖都标全了，这里只补三个"为什么"：`damage = 66` 是第 06 集的老朋友（pap 骨同款伤害）；`inv_timer = 6/30`（0.2 秒）是 sans 骨"帧伤"的同款思路——光束每 0.2 秒咬一口。至于"库的参数怎么盖"：库的子弹就是普通 Bullet 子类，字段公开——先看库源码里各字段的默认值（`libraries/gaster_blaster/scripts/battle/bullets/gaster_blaster.lua`），再在 spawnBullet 之后覆盖，这也是用任何库的通用套路。发射时的震屏（shakeCamera）、碰撞体（Hitbox）、三层光柱全是库自己干的——"库负责发炮，波次负责进场"，各管一段。

然后是"打谁"——加权随机：

```lua
-- GB 目标权重：Kris 和 Ralsei 比 Susie 更容易被选中
local TARGET_WEIGHTS = {
    {id = "kris", weight = 2},
    {id = "ralsei", weight = 2},
    {id = "susie", weight = 1},
}

-- 按权重随机挑一个目标：权重越大，被选中的概率越高
local function pickGBTarget()
    local candidates = {}
    local total_weight = 0

    -- 只收集还能成为目标的人（canTarget 由引擎判断，倒下/退场的会被排除）
    for _, entry in ipairs(TARGET_WEIGHTS) do
        local battler = Game.battle:getPartyBattler(entry.id)
        if battler and battler:canTarget() then
            total_weight = total_weight + entry.weight
            table.insert(candidates, {
                battler = battler,
                weight = entry.weight,
            })
        end
    end

    -- 没人能打：让引擎随便挑一个
    if total_weight == 0 then
        return Game.battle:randomTarget()
    end

    -- 加权抽签：随机数落在谁的权重区间里，谁中标（权重 2 的区间是权重 1 的两倍）
    local roll = love.math.random() * total_weight
    for _, candidate in ipairs(candidates) do
        roll = roll - candidate.weight
        if roll < 0 then
            return candidate.battler
        end
    end

    return candidates[#candidates].battler
end
```

权重逻辑注释里都标了。唯一的悬念：为什么苏西权重低？——看到第 08 集的"苏西的反应"就懂了——我们得给苏西说话的概率大一些（笑）

再补一个库自带的隐藏福利：**擦弹给 TP**。库子弹默认 `tp = 1.6`——擦弹（贴着光束边缘蹭过去）时给团队加 TP。引擎 Bullet 基类注释原话："TP added when you graze this bullet (Also given each frame after the first graze, 30x less at 30FPS)"——首次擦弹给一次，之后每帧继续给一点（30fps 下是首擦的 1/30）。顺带 `time_bonus = 1`：擦弹还减回合时间。这就是"擦弹攒 TP"的机制基础——TP 攒起来才能放 ACT。
