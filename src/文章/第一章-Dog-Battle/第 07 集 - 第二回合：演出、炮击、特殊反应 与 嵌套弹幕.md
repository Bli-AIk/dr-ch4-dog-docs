## 规划第二回合的变化

老规矩，动手前先拆（第 03 集的方法论）。第二回合在第一回合的基础上加两块变化：

- **开头敌人演出**：第一回合是"直接放弹幕"；第二回合开打前，狗先表演一段——旋转、变白、吸收粒子、蓝色雾气，气氛拉满再开炮；

这集的东西比上一集多，但别慌：演出大部分是"组装框架现成的能力"，真正手写的没几处。演出链条先记住，后面一步步实现：**旋转 → 变白 → 粒子吸收 → 蓝色雾气 → 中央矩形 → 眼睛 → 发射**。分析，然后实现。

## 开头演出：转圈、变白、吸收粒子

先看狗在动画里干了什么（第 03 集任务清单里写的"第二回合的蓄力（转圈、发光、吸收粒子）和 GB 炮"）：旋转——spin 动画连转三圈；变白——白色覆盖整个狗；粒子吸收——白色粒子从周围飞向中心；蓝色雾气——一圈蓝雾收拢成一条线。这一段是纯演出：不打伤害、不读输入，就是把气氛顶上去。

先看整段演出的"指挥"——`scripts/battle/waves/gb.lua` 的 onStart（完整文件在模组里，这里贴关键段）：

```lua
-- 循环播放 spin 动画，loops_left 次
local function playSpin(battler, loops_left, callback)
    battler:setAnimation({ "spin/spin", 1 / FPS, false }, function()
        if loops_left > 1 then
            playSpin(battler, loops_left - 1, callback)
        else
            callback()
        end
    end)
end

function GB:onStart()
    Assets.playSound("snd_knight_stretch", 1, 0.75)

    local attackers = self:getAttackers()
    self.dog = attackers[1]

    self.party_health = {}
    for _, battler in ipairs(Game.battle.party) do
        self.party_health[battler.chara.id] = battler.chara:getHealth()
    end

    if not self.dog then
        self:spawnBlaster()
        return
    end

    self.dog.current_target = pickGBTarget()

    self:spawnCircle()
    self.white_fx = self.dog:addFX(ColorMaskFX({1, 1, 1}, 0), "gb_white")
    self.timer:tween(SPIN_TIME * (SPIN_LOOPS - 1) / SPIN_LOOPS, self.white_fx, {amount = 1}, "linear")
    self:spawnParticle()
    self.particle_spawn_timer = self:getParticleSpawnInterval()
    self.timer:after(SPIN_TIME - CENTER_RECTANGLE_TIME, function()
        if self.dog then
            self:spawnCenterRectangle()
        end
    end)

    playSpin(self.dog, SPIN_LOOPS, function()
        Assets.playSound("snd_dogresidue")
        self:spawnEye()
        self:spawnDogFlash()
        self:spawnBlaster()
    end)
end
```

`playSpin` 是递归播放：spin 动画播完一次，还有次数就再播一次，全转完才回调——"转三圈然后进下一段"就这么实现的。onStart 的流程：先放音效 `snd_knight_stretch`（起手音）；`pickGBTarget()` 锁定目标（炮击节讲）；起雾（spawnCircle）、白色覆盖渐显（`ColorMaskFX`，amount 从 0 缓动到 1）、粒子开始生成；转圈快结束时中央矩形收缩（spawnCenterRectangle）——把"吸力"聚焦成一条线；转圈完毕放 `snd_dogresidue`，眼睛睁开（spawnEye）、复制体放大淡出（spawnDogFlash）；最后 `spawnBlaster()` 发射。

先看雾气——GBCircle。它是个 Object 子类，干的事是"给圆套一层迷雾 shader"：

```lua
-- 圆形使用的迷雾 shader 文件
local MIST_SHADER_PATH = Mod.info.path .. "/assets/shaders/gb_mist.frag"

local GBCircle, circle_super = Class(Object)

function GBCircle:init(x, y, radius)
    circle_super.init(self, x, y, radius * 2, radius * 2)

    self.radius = radius
    self.alpha = 0
    self.white_amount = 0
    self.time = 0
    self.shader = love.graphics.newShader(MIST_SHADER_PATH)
end

function GBCircle:update()
    circle_super.update(self)
    self.time = self.time + DT
end

function GBCircle:draw()
    local old_shader = love.graphics.getShader()
    local old_r, old_g, old_b, old_a = love.graphics.getColor()

    self.shader:send("time", self.time)
    self.shader:send("white_amount", self.white_amount)

    love.graphics.setShader(self.shader)
    love.graphics.setColor(1, 1, 1, self.alpha)
    love.graphics.circle("fill", 0, 0, self.radius, CIRCLE_SEGMENTS)
    love.graphics.setColor(old_r, old_g, old_b, old_a)
    love.graphics.setShader(old_shader)
end
```

`love.graphics.newShader(MIST_SHADER_PATH)` 加载迷雾着色器（`assets/shaders/gb_mist.frag`），每帧把 time 和 white_amount 用 `shader:send` 传进去，画圆时套上。shader 我们直接用了没改——想改雾的形状、颜色，改那个 .frag 文件就行。shader 是演出利器，以后还会用（草，这集的演出密度是真的高）。

然后是"吸收粒子"——为什么叫"吸收"？因为粒子是从周围**飞向中心**的。GBParticle：

```lua
local GBParticle, particle_super = Class(Object)

function GBParticle:init(x, y, target_x, target_y, radius, travel_time)
    particle_super.init(self, x, y, radius * 2, radius * 2)

    self.start_x = x
    self.start_y = y
    self.target_x = target_x
    self.target_y = target_y
    self.radius = radius
    self.travel_time = travel_time
    self.progress = 0
    self.layer = 1
end

function GBParticle:update()
    particle_super.update(self)

    self.progress = self.progress + DT / self.travel_time
    local progress = math.min(self.progress, 1)
    local eased_progress = 1 - (1 - progress) ^ 3

    self.x = self.start_x + (self.target_x - self.start_x) * eased_progress
    self.y = self.start_y + (self.target_y - self.start_y) * eased_progress

    if self.progress >= 1 then
        self:remove()
    end
end

function GBParticle:draw()
    local old_r, old_g, old_b, old_a = love.graphics.getColor()

    love.graphics.setColor(1, 1, 1, 1)
    love.graphics.circle("fill", 0, 0, self.radius, CIRCLE_SEGMENTS)
    love.graphics.setColor(old_r, old_g, old_b, old_a)
end
```

三个变量：起点、终点（圆心）、飞行时间。每帧按缓动推进进度，到点就 `remove()`。关键在缓动：`1 - (1 - progress) ^ 3`——ease-out-cubic（第 06 集 easings.net 那课说过的"演出用缓动"）：开头快、收尾慢，像被吸过去。粒子的生成节奏在 `GB:update` 里控制——`getParticleSpawnInterval` 用 `math.sqrt(love.math.random())` 让"较长的间隔更常出现"，粒子越到后面越稀疏，不会糊成一团。

## 制作炮击攻击：先找轮子

炮击——GB（Gaster Blaster，审判眼）。这一节先坦白：我们最初的 GB 是**手搓的**——自己写子弹类、自己画光柱。后来在社区发现一个现成的库 `gaster_blaster`（v0.0.1，作者 Scarm、JustAnotherRandomUser、Toby Fox），就把手搓版换了——手感、动画都比自己写的强。这就是 EX05 说的"先找轮子"：写完才发现有现成的，下次先搜（草）。

装库很简单：把库文件夹放进项目的 `libraries/` 目录。引擎启动时扫描 `libraries/` 下的每个子目录，解析里面的 `lib.json`（库的"身份证"，id 是 `gaster_blaster`），注册进项目；库的脚本会被自动挂载——`scripts/battle/bullets/` 下的文件按文件名注册成子弹 ID。装完库，`spawnBullet("gaster_blaster", ...)` 就能用了。

库自带一个测试波次 `gb_test.lua`（47 行），等于官方 API 手册——`spawnBullet` 的全部参数一目了然：

```lua
---@class GBTest : Wave
local GBTest, super = Class(Wave)

function GBTest:init()
    super.init(self)
    self.time = 8
end

function GBTest:onStart()
    local arena = Game.battle.arena
    local center_x, center_y = arena:getCenter()
    local arena_top = arena:getTop()
    local arena_right = arena:getRight()

    -- A vertical shot from above. The beam stays active long enough to show
    -- both frame damage and repeated graze TP.
    self:spawnBullet(
        "gaster_blaster",
        center_x,
        arena_top - 80,
        0,
        center_x,
        arena_top + 18,
        0,
        45,
        45,
        true
    )

    -- Follow with a horizontal shot to demonstrate rotation and exit motion.
    self.timer:after(2.5, function()
        self:spawnBullet(
            "gaster_blaster",
            arena_right + 80,
            center_y,
            90,
            arena_right - 18,
            center_y,
            90,
            45,
            45,
            true
        )
    end)
end

return GBTest
```

九个参数：x、y（生成位置）、rot（角度——注意是**度**不是弧度，库内部自己转）、target_x、target_y（滑向的目标位置）、target_rot（目标角度）、wait_time（到位后等待的帧数）、blast_time（光束持续时长）、play_sound（带不带音效）。

gb_test 是库的"默认用法"；我们的 gb.lua 玩得更进阶——**把库的进场接管过来**。看 spawnBlaster：

```lua
function GB:spawnBlaster()
    local arena = Game.battle.arena
    local center_x = arena:getCenter()
    local top_y = arena:getTop() + 18
    local start_y = -120
    local final_y = top_y - 50

    local bullet = self:spawnBullet(
        "gaster_blaster",
        center_x,
        start_y,
        90,
        center_x,
        start_y,
        0,
        math.huge,
        BLAST_TIME,
        true
    )
    bullet.damage = BLAST_DAMAGE
    bullet.inv_timer = BLAST_INVULN_TIME

    -- Skip the library's linear approach and let the wave own the entry
    -- motion. The final point stays above the arena's top position.
    bullet.state = 1
    bullet.target_x = center_x
    bullet.target_y = start_y
    bullet.target_rot = 0

    self.timer:tween(
        ENTRY_TIME,
        bullet,
        {y = final_y, rotation = 0},
        "out-cubic",
        function()
            bullet.wait_time = WAIT_FRAMES
        end
    )

    if self.dog then
        self.dog:setAnimation("idle")
    end

    if self.white_fx then
        local white_fx = self.white_fx
        white_fx.amount = 1
        self.timer:tween(
            WHITE_FADE_TIME,
            white_fx,
            {amount = 0},
            "out-cubic",
            function()
                if self.dog and white_fx.parent == self.dog then
                    self.dog:removeFX(white_fx)
                end
                if self.white_fx == white_fx then
                    self.white_fx = nil
                end
            end
        )
    end
end
```

拆开说：

- `spawnBullet("gaster_blaster", center_x, start_y, 90, ...)`——从战斗框正上方 90° 滑入；
- `bullet.damage = 66`、`bullet.inv_timer = 6 / 30`——**覆盖库的默认值**。库的子弹默认 `damage = nil`（库注释里写了：没加 KR，见 Bullet 基类的默认伤害处理）、`inv_timer = 4/3`（受击无敌 4/3 秒）。66 是第 06 集的老朋友（pap 骨同款伤害）；6/30 = 0.2 秒——光束每 0.2 秒结算一次伤害，sans 骨"帧伤"的同款思路；
- `bullet.state = 1`——最值钱的一行。库的子弹默认自己"滑向目标"（state 0 的线性逼近：每帧朝目标挪 1/3 距离），我们把状态直接拨到 1（等待发射），**进场演出由波次接管**：`tween(ENTRY_TIME, bullet, {y = final_y, rotation = 0}, "out-cubic")` 优雅滑入，到位后设 `bullet.wait_time = WAIT_FRAMES`（15 帧）才开始蓄力。发射时的震屏（shakeCamera）、碰撞体（Hitbox）、三层光柱（draw 里那几根线）全是库自己干的——"库负责发炮，波次负责进场"，各管一段。

"库的参数怎么盖"：库的子弹就是普通 Bullet 子类，字段公开——先看库源码里各字段的默认值（`libraries/gaster_blaster/scripts/battle/bullets/gaster_blaster.lua`），再在 spawnBullet 之后覆盖。这也是用任何库的通用套路。

然后是"打谁"——加权随机：

```lua
-- GB 目标权重：Kris 和 Ralsei 比 Susie 更容易被选中
local TARGET_WEIGHTS = {
    {id = "kris", weight = 2},
    {id = "ralsei", weight = 2},
    {id = "susie", weight = 1},
}

local function pickGBTarget()
    local candidates = {}
    local total_weight = 0

    for _, entry in ipairs(TARGET_WEIGHTS) do
        local battler = Game.battle:getPartyBattler(entry.id)
        if battler and battler:canTarget() then
            total_weight = total_weight + entry.weight
            table.insert(candidates, {
                battler = battler,
                weight = entry.weight,
            })
        end
    end

    if total_weight == 0 then
        return Game.battle:randomTarget()
    end

    local roll = love.math.random() * total_weight
    for _, candidate in ipairs(candidates) do
        roll = roll - candidate.weight
        if roll < 0 then
            return candidate.battler
        end
    end

    return candidates[#candidates].battler
end
```

克里斯和利艾尔斯权重 2、苏西权重 1——GB 更爱点名前两位（倒下的队员会被 `canTarget` 过滤掉，全倒就 `randomTarget` 兜底）。为什么苏西权重低？看到下面的"特殊反应"就懂了。

再补一个库自带的隐藏福利：**擦弹给 TP**。库子弹默认 `tp = 1.6`——擦弹（贴着光束边缘蹭过去）时给团队加 TP。引擎 Bullet 基类注释原话："TP added when you graze this bullet (Also given each frame after the first graze, 30x less at 30FPS)"——首次擦弹给一次，之后每帧继续给一点（30fps 下是首擦的 1/30）。顺带 `time_bonus = 1`：擦弹还减回合时间。这就是"擦弹攒 TP"的机制基础——TP 攒起来才能放 ACT（第 05 集讲过）。

## 加入特殊反应

第二回合打完，苏西会开口——说什么，看战况。

**第一件：苏西的开心待机**。在狗的战斗里，苏西的待机动画从普通版换成"开心"版。实现是 hook（第 05 集教过：HookSystem.hookScript 挂接引擎类，不篡改引擎源码）：

```lua
---@class PartyBattler
local PartyBattler, super = HookSystem.hookScript(PartyBattler)

function PartyBattler:setAnimation(animation, callback)
    if animation == "battle/idle"
        and self.chara
        and self.chara.id == "susie"
        and Game.battle
        and Game.battle.encounter
        and Game.battle.encounter.id == "dog"
    then
        self.actor.offsets["battle/idle_happy"] = self.actor.offsets["battle/idle"] or { 0, 0 }
        animation = { "battle/idle_happy", 1 / 6, true }
    end

    return super.setAnimation(self, animation, callback)
end

return PartyBattler
```

`setAnimation` 被拦截：只要是在狗的战斗里、且苏西要播 `battle/idle`，就换成 `battle/idle_happy`——偏移量（offsets）从 `idle` 复制，所以只有表情变，位置不漂。苏西"太酷了"的反应就有了视觉锚点。

**第二件：战况叙述分三档**。狗在回合结束时记战况，下一回合开头用旁白汇报。`getEncounterText` 是引擎"回合开头敌人说话"的入口（第 05 集 dummy 的对话也走这里）。看 dog.lua 新增的两个函数（完整文件第 05 集见过，这里是加的部分）——先看"读战况"的 getEncounterText：

```lua
function Dog:getEncounterText()
    if self.gb_narration_pending then
        self.gb_narration_pending = nil

        local party_health = self.gb_party_health
        local someone_was_down = self.gb_party_was_down
        self.gb_party_health = nil
        self.gb_party_was_down = nil

        if someone_was_down then
            return Game:loc("battle_dog_gb_kris_downed"), "teeth_b", "susie"
        end

        local damaged_battlers = {}
        for _, battler in ipairs(Game.battle.party) do
            local starting_health = party_health and party_health[battler.chara.id]
            if starting_health and battler.chara:getHealth() < starting_health then
                table.insert(damaged_battlers, battler)
            end
        end

        if #damaged_battlers == 1 and damaged_battlers[1].chara.id == "susie" then
            return Game:loc("battle_dog_gb_kris_downed"), "teeth_b", "susie"
        elseif #damaged_battlers > 0 then
            local lowest_health_battler = nil
            for _, battler in ipairs(Game.battle.party) do
                if battler.chara.id ~= "susie"
                    and (not lowest_health_battler
                        or battler.chara:getHealth() < lowest_health_battler.chara:getHealth())
                then
                    lowest_health_battler = battler
                end
            end

            local name = lowest_health_battler
                and Game:locText("[name:" .. lowest_health_battler.chara.id .. "]")
                or Game:locText("[name:kris]")
            return Game:loc("battle_dog_gb_damaged", {name = name}), "intense_angry", "susie"
        else
            return Game:loc("battle_dog_gb_undamaged"), "surprise_smile", "susie"
        end
    end

    return super.getEncounterText(self)
end
```

再配合"记战况"的 onTurnEnd——回合结束时被引擎调用：

```lua
function Dog:onTurnEnd()
    if self.selected_wave ~= "gb" then
        self.gb_narration_pending = false
        self.gb_party_health = nil
        self.gb_party_was_down = nil
        return
    end

    local susie = Game.battle:getPartyBattler("susie")
    self.gb_party_was_down = false
    for _, battler in ipairs(Game.battle.party) do
        if battler.is_down then
            self.gb_party_was_down = true
            break
        end
    end

    self.gb_narration_pending = susie and not susie.is_down or false
    if not self.gb_narration_pending then
        self.gb_party_health = nil
        self.gb_party_was_down = nil
    end
end
```

流程：`onTurnEnd` 确认这回合是 gb（不是就清空状态）；记录有没有人倒下（`gb_party_was_down`）、苏西是不是还活着——**苏西活着才留叙述**（`gb_narration_pending`）。下一回合 `getEncounterText` 按战况分档，返回三个值：文案、表情、说话人（都是苏西说）：

- 有人倒下 → "* 搞什么？！这玩意儿伤害这么高？！"（teeth_b 表情）——不管倒下的是谁，都是这句（文案写死了，想更讲究可以自己改）；
- 没人倒下但有人受伤 → "* 靠！[名字]，你是在用脸接大炮吗？！"（intense_angry 表情）——名字取血量最低的那位（`Game:locText("[name:" .. id .. "]")`，名字用语言占位，跟着语言走）；
- 全员无伤 → "* 我去，大炮？！这太酷了！"（surprise_smile 表情）。

留意 `Game:loc("battle_dog_gb_damaged", {name = name})`——这是第 05 集说的 `Game:loc` 兜底用法：叙述文本是"拼好的字符串"（带 `[var:name]` 富文本占位），不是台词表里现成的 `{key}`，所以在代码里解析。文案原文在 `lang/zh_hans.json` 的 `battle_dog_gb_*` 三个键里——分档逻辑在 dog.lua，文案随便改。
